# dirsync

Консольная утилита на Go для односторонней синхронизации директорий. Она приводит директорию назначения к точной копии исходной: копирует новые файлы, обновляет изменённые и удаляет лишние.

Файлы сравниваются по содержимому (SHA-256), а не по дате изменения, поэтому синхронизация не зависит от того, трогали ли файл без изменений.

## Возможности

- **Рекурсивный обход** — учитываются файлы во всех вложенных папках, включая скрытые.
- **Сравнение по хешу SHA-256** — обновляются только файлы, содержимое которых действительно отличается.
- **Параллельное хеширование** — файлы обрабатываются пулом воркеров, а исходная и целевая директории сканируются одновременно.
- **Три типа операций:**
  - копирование файлов, которых нет в назначении;
  - обновление файлов с отличающимся содержимым;
  - удаление файлов, которых нет в источнике.
- **Автоматическое создание вложенных папок** при копировании.
- **Прогресс-бар** и **цветной отчёт** об операциях:
  - зелёный — `[КОПИРОВАНИЕ]`
  - жёлтый — `[ОБНОВЛЕНИЕ]`
  - красный — `[УДАЛЕНИЕ]`
- **Устойчивость к ошибкам** — если один файл не удалось обработать, синхронизация остальных продолжается, а ошибки выводятся в `stderr` в конце.

## Установка и сборка

Требуется **Go 1.26** или новее (см. `go.mod`).

### Сборка из исходников

```bash
git clone https://github.com/egorka-hub/dirsync.git
cd dirsync
go build -o dirsync
```

После сборки в папке появится исполняемый файл `dirsync`.

### Установка через `go install`

```bash
go install github.com/egorka-hub/dirsync@latest
```

Бинарник будет установлен в `$(go env GOPATH)/bin` — убедитесь, что эта папка есть в `PATH`.

### Запуск без сборки

```bash
go run . <source> <dest>
```

## Использование

```bash
dirsync <source> <dest>
```

| Аргумент | Описание |
|---|---|
| `<source>` | Исходная директория — эталон, из которого берутся файлы |
| `<dest>` | Директория назначения — будет приведена к копии `<source>` |

> **Внимание:** синхронизация односторонняя. Файлы в `<dest>`, которых нет в `<source>`, **будут удалены**. Директория `<dest>` должна существовать.

## Примеры использования

### Синхронизация с изменениями

```bash
$ ./dirsync ./source ./backup
Синхронизация...
 100% |███████████████████████████████████████| (3/3)
[КОПИРОВАНИЕ] a.txt
[ОБНОВЛЕНИЕ] b.txt
[УДАЛЕНИЕ] c.txt

Синхронизация завершена!
Скопировано: 1
Обновлено: 1
Удалено: 1
```

### Директории уже совпадают

```bash
$ ./dirsync ./source ./backup
Директории уже синхронизированы, делать нечего.
```

### Ошибка в аргументах

```bash
$ ./dirsync ./source
usage: dirsync <source> <dest>
```

### Быстрая проверка на тестовых данных

```bash
mkdir -p source backup
echo "a"      > source/a.txt
echo "новое"  > source/b.txt
echo "старое" > backup/b.txt
echo "c"      > backup/c.txt

./dirsync ./source ./backup
```

Папки `source/` и `backup/` добавлены в `.gitignore`, поэтому не попадут в репозиторий.

## Как это работает

1. **Сканирование** — обе директории обходятся рекурсивно, для каждого файла считается SHA-256. Источник и назначение сканируются параллельно.
2. **Сравнение** — по относительным путям и хешам файлы раскладываются на три списка: скопировать, обновить, удалить.
3. **Синхронизация** — операции выполняются по очереди, прогресс отображается в баре.
4. **Отчёт** — после завершения выводится цветной список операций, ошибки и итоговая статистика.
